# Uni-D 배터리 열폭주 6단계 분류 — 17팀

열화상 이미지 + 센서 시계열로 각 관측 시점의 열폭주 단계(1~6)를 분류합니다.
센서 시계열 LightGBM(테이블 피처 266개 + 규칙 피처 30개)과 열화상 CNN(현재·직전 프레임 비교)을 후기 융합한 뒤,
2·3단계로 나온 행만 압력 상승 피처를 더한 두 번째 LightGBM으로 다시 판정합니다.
마지막으로 5·6단계 예측은 그 단계의 이벤트를 관측한 뒤에만 인정하고 (5단계: 온도 급상승 또는 두 번째 전압 강하, 6단계: 온도 합이 더 오르지 않음),
4·5단계는 한 번 넘어가면 되돌아가지 않게 합니다.

## 팀 정보
- 팀명: 17팀
- 최종 선택 제출 파일: `sub18_final_v9.csv`, Private 복원 대상 (`python test.py`의 출력과 바이트 단위로 같음)

## 개발 환경
- OS: Ubuntu 22.04.5 LTS (jammy)
- Python: 3.10.12
- GPU: 대회 제공 GPU 서버, NVIDIA GeForce RTX 5080 (16GB), 드라이버 580.178.04, CUDA 12.8
- 주요 라이브러리 (실행 확인 버전): torch 2.11.0+cu128, torchvision 0.26.0, timm 1.0.31, lightgbm 4.7.0,
  scikit-learn 1.7.2, pandas 2.3.3, numpy 2.2.6, pillow 12.3.0, joblib 1.6.0 (`requirements.txt` 참고)

## 파일 구성
| 파일 | 역할 |
|---|---|
| `model.py` | 이미지 경로 연결, 이미지 색 통계, 테이블·규칙·압력 상승 피처, LightGBM 설정, CNN 구조·전처리·결정적 추론, 융합, 2·3단계 재판정, 5·6단계 근거 확인, 원통형 4단계 최소 길이, 되돌아가지 않기, 6단계 진입(각형) |
| `train.py` | Train → Validation 평가, Train+Validation 전체 최종 학습, 가중치 저장 |
| `test.py` | `weights/` 로드 → 입력 CSV의 행만으로 추론 → 제출 파일 생성 (학습·fit 없음) |
| `weights/tab_lgbm.joblib` | LightGBM 기본 모델 + 2·3단계 재판정 모델 + 피처 열 순서 + 배터리 구성별 압력 범위 중앙값 표 + 피처·모델·융합 설정 |
| `weights/cnn_pairdiff.pt` | 이미지 CNN 가중치 (fp16 state_dict, 추론 시 float32로 올림) |

## 실행 방법
```bash
pip install -r requirements.txt

# 추론 (가중치는 기본값 weights/ 사용, GPU가 있으면 GPU, 없으면 CPU)
python test.py --input <battery_data_light 경로>/test/test.csv \
               --image_root <battery_data_light 경로>/test \
               --output submission.csv
# (선택) --sample_submission <경로>/sample_submission.csv : 제출 양식 행 순서로 저장 (기본은 입력 CSV 행 순서)

# 학습 (선택) → 평가 점수 출력 + weights/tab_lgbm.joblib 저장 + CNN 가중치 준비
python train.py --data_dir <battery_data_light 경로>              # 테이블 평가 + 최종 학습
python train.py --data_dir <battery_data_light 경로> --eval_cnn   # + Train만으로 CNN 학습해 융합 점수까지 (GPU)
python train.py --data_dir <battery_data_light 경로> --train_cnn  # 최종 CNN도 새로 학습 (GPU)
```
- `test.py`는 학습·fit을 하지 않습니다. 입력 CSV에 있는 행만 보고 피처를 만들기 때문에 행 순서를 섞거나,
  실험 일부만 넣거나, 실험별 앞부분만 넣어도 같은 행에는 같은 예측이 나옵니다. 출력은 입력 CSV의 행 순서입니다.
- 실행 시간 (Test 3,451행, 라이브러리 로딩 포함): GPU 약 11초, CPU만 사용 시 약 30초. GPU와 CPU의 예측 라벨은 Test 전체에서 같았습니다
  (CNN 확률 차이 최대 1.2e-6).
- CNN 추론은 결정적 설정입니다: `model.eval()` + `torch.no_grad()`, TF32 끔, `cudnn.deterministic=True`,
  `cudnn.benchmark=False`, **이미지 1장씩 추론**(배치 구성에 따른 수치 차이 제거).
- LightGBM 학습은 결정적 설정(`deterministic=True`, `force_row_wise=True`, `random_state=42`, `n_jobs=4`)이라
  `train.py`를 다시 실행해도 같은 테이블 모델(기본·재판정 둘 다)이 나옵니다.
- **CNN 가중치에 대해**: GPU 학습은 비트 단위로 재현되지 않습니다. 그래서 `train.py`는 기본적으로 제출에 사용한
  학습 완료 가중치를 `weights/cnn_pairdiff.pt`로 복사하고, CNN 재학습은 `--train_cnn`을 줄 때만 합니다
  (같은 코드·설정이지만 결과 가중치는 조금 다를 수 있음). **제출 결과를 만든 가중치는 레포의 `weights/cnn_pairdiff.pt`입니다.**
  이 가중치는 실험 단계에서 `experiments/img/finetune2.py --full`로 학습한 것이고, `train.py`의 `train_cnn`은 그와 같은
  하이퍼파라미터·증강·가중을 옮긴 것입니다. 복사할 원본이 없는 환경에서는 `train.py`가 레포의 기존 가중치를 그대로 둡니다.

## 모델 구성
아래에서 '학습 실험'은 라벨이 있는 Train + Validation 97개 실험 전체를 말합니다. 4~9번 규칙의 구조와 상수는 이 97개를 모두 보고 정했습니다.

1. **테이블 모델**: LightGBM 다중 분류 (learning_rate 0.1, 200 trees, num_leaves 31, min_child_samples 40,
   subsample 0.8, colsample_bytree 0.3, max_bin 63, reg_lambda 1.0). 입력은 아래 시계열 피처 266개 + 규칙 피처 30개.
2. **이미지 모델 (pairdiff CNN)**: timm `resnet18` (ImageNet 사전학습) 미세조정. 입력 9채널 =
   현재 프레임 RGB + 같은 실험의 직전 관측 프레임 RGB + 두 프레임의 차이, 128×128. 출력 6단계 확률.
   - 학습: Train+Validation 전체, 직전 프레임은 5/10/15초 전 중 무작위 (Test의 10·15초 간격 대응),
     좌우 반전·크기·이동 증강, 클래스 가중 1/n, 긴 실험은 500행 상한 비중, 8 epoch(1,496 step, 배치 128), AdamW + OneCycle.
   - 추론: 직전 프레임 = 입력 CSV에 있는 같은 실험의 행 중 시간상 바로 앞 관측 (실험 첫 행은 자기 자신).
3. **융합**: `P ∝ P_tab^0.8 · P_cnn^0.2` (가중치 0.2 고정) → `label = argmax + 1`. 순서 보정·클래스 가중은 쓰지 않습니다
   (검증에서 이득 없음).
4. **2·3단계 재판정**: 3의 결과가 2 또는 3인 행만, 재판정 모델의 2단계·3단계 확률 중 큰 쪽으로 다시 정합니다.
   1·4·5·6단계 예측은 그대로 둡니다.
   - 재판정 모델: 1과 같은 설정의 LightGBM 6단계 분류. 입력 = 1의 296개 + 압력 상승 피처 48개 (아래 "시계열 피처 구성").
   - 재판정에는 이미지 확률을 섞지 않습니다. 2·3단계 경계는 압력 변화로 정해져 열화상에 드러나지 않고,
     검증에서도 섞지 않는 쪽이 같거나 나았습니다 (제공 분할에서 CNN 시드 3개 모두 +0.003~0.005, 교차검증에서는 차이 없음).
5. **5단계 근거 확인**: 각형 28Ah 가열·각형 280Ah 과충전 실험에서 5단계 이상(5·6단계)으로 나온 행은, 전압 급락 이후 온도 급상승
   (직전 관측 대비 0.84℃/s 이상, 또는 10초 이상 전의 가장 가까운 관측 대비 12℃ 이상)을 한 번이라도 관측한 뒤에만 인정하고 그 전이면 4단계로 되돌립니다.
   - 이 두 구성의 5단계는 "4단계 이후 온도가 급상승하는 지점"입니다. 학습 실험 23개 전부에서 위 조건은 5단계 시작 +0~+2행에
     처음 참이 되고, 4단계 동안에는 한 번도 참이 아니었습니다. 과거 관측과 고정 상수만 씁니다.
   - 넣은 이유: 행 모델은 4단계가 학습 실험보다 길어지면 온도 급상승 없이도 "시간이 지났으니 5단계"로 넘깁니다.
     검증 실험의 4단계 구간을 복제해 5배로 늘린 합성 검증에서, 제약이 없으면 늘어난 4단계 행 중 각형 28Ah 328행·각형 280Ah
     과충전 127행을 5단계로 예측했고(Macro F1 0.948 → 0.878, 0.882 → 0.816), 제약을 넣으면 0행이었습니다.
     평상시 교차검증에서는 중립입니다(−0.0001).
   - 원통형 4.8Ah·6Ah 가열에도 같은 방식의 확인을 둡니다. 이 구성의 5단계는 "4단계 이후 전압이 다시 25% 이상 떨어진 지점"이므로,
     첫 전압 급락 뒤 30초가 지난 시점부터 "직전 15초 최고 전압의 75% 이하로 떨어진 적이 있다"를 관측하기 전의 5·6단계 예측은
     4단계로 되돌립니다. 전압이 첫 급락에서 이미 0V 근처로 내려간 실험에도 같은 비율 기준을 씁니다.
     학습 실험 31개 중 26개에서 이 조건은 5단계 시작 행에 정확히 처음 참이 되고(±1행 이내 28개), 끝까지 참이 되지 않는 실험은 없습니다.
     교차검증에서 바뀐 행은 모두 정답 쪽이었습니다 (근거 확인 전체 +0.0009; 30초·0V 근처 처리만의 효과는 +0.0005, 개선 확률 0.86).
     4단계를 5배로 늘린 합성 검증에서 Macro F1 0.825 → 0.896.
6. **6단계 근거 확인** (5번보다 먼저 적용): 6단계로 나온 행이라도 온도 합(`meas_t1 + meas_t2`)의 현재 값이 지금까지의 최고점이면
   5단계로 둡니다. 6단계는 온도 합이 최고점에 이른 시점부터이므로, 아직 내려오기 시작하지 않았으면 최고점이 지났다고 볼 수 없기 때문입니다.
   교차검증에서 해당 54행 중 37행이 정답으로 바뀌고 14행이 오답으로 바뀌었습니다 (+0.0024, 개선 확률 1.00).
   "초당 0.2℃ 넘게 오를 때만" 적용하는 변형도 교차검증 점수는 같았지만, 5단계가 2~3배 느리게 진행되는 합성 검증에서
   속도 조건이 없는 쪽이 더 견고했습니다 (Macro F1 0.9075 → 0.9124, 0.8883 → 0.8992).
   반대 방향("최고점 갱신이 멈춘 지 오래면 6단계")은 중간 봉우리가 흔해서 크게 해로워 넣지 않았습니다.
7. **원통형 4단계 최소 길이**: 원통형(4.8Ah·6Ah 가열)에서는 4단계에 들어선 뒤 30초가 지나기 전의 5단계 이상 판정을 4단계로 둡니다.
   학습 원통형 31개 실험의 4단계는 모두 30초 이상이고(정확히 30초가 3개), 전압이 20초 만에 0V까지 내려간 실험도 5단계 라벨은
   30초 시점에 시작합니다 — 전압 강하 판정이 15초 창과 복귀 확인을 쓰기 때문으로 보입니다. 행 모델은 첫 강하가 두 행에 걸쳐 이어질 때
   이를 두 번째 강하로 보고 5단계를 일찍 내는 경우가 있습니다. 교차검증에서 31행이 정답으로 바뀌고 오답으로 바뀐 행은 없었습니다
   (+0.0008, 개선 확률 0.95; 하한을 학습 fold에서만 구해도 +0.0006 / 0.95). 다른 구성·다른 단계의 최소 길이 제약은 손해라 넣지 않았습니다.
8. **되돌아가지 않기** (5~7번 뒤에 적용): 같은 실험의 앞선 시점에 4단계(또는 5단계) 이상으로 판정한 적이 있으면 그 아래로 내려가지 않게 합니다.
   4단계를 굳히는 것은 전압 급락을 관측한 뒤부터입니다 (교차검증 결과는 같고, 3단계가 느리게 진행되는 합성 검증에서 근거 없는 4단계가 굳는 것을 막음).
   라벨은 97개 실험 모두 단계가 뒤로 가지 않는데, 행 단위 모델은 4단계 이후에 가끔 낮은 단계로 되돌아갑니다.
   교차검증 +0.0057 (개선 확률 0.98; Test에 있는 배터리 구성만 보면 +0.0020 / 0.96; 이득이 가장 큰 실험 하나를 빼도 +0.0016 / 0.92).
   3단계와 6단계에는 적용하지 않습니다 — 첫 판정이 이른 경우가 많아 굳히면 손해였습니다(각 −0.0005).
   근거 확인 뒤에 적용하므로 근거 없이 넘긴 판정이 굳어지지 않습니다 (4단계 구간을 늘린 합성 검증으로 확인).
9. **6단계 진입 (각형, 마지막에 적용)**: 각형 28Ah 가열·각형 280Ah 과충전에서 온도 급상승을 본 뒤 온도 합(`meas_t1 + meas_t2`)이
   현재의 최고점보다 30℃ 넘게 내려온 적이 있으면, 그때부터 5단계 판정을 6단계로 올립니다 (더 높은 최고점이 새로 나오면 다시 해제).
   6단계는 온도 합의 최고점부터인데, 행 모델은 최고점이 지난 뒤에도 몇 행 동안 5단계에 머무는 경우가 있습니다.
   이 두 구성의 학습 실험 23개에서 5단계 동안의 최고점 대비 하강은 최대 24.5℃였고, 라벨 전체에서 이 조건이 참인데 5단계 이하인 행은 없습니다.
   교차검증에서 회당 10.7행이 정답으로 바뀌고 오답으로 바뀐 행은 없었습니다 (+0.0012, 개선 확률 0.96).
   원통형은 5단계 중에 온도 합이 크게 내려갔다 다시 오르는 일이 많아 적용하지 않습니다 (적용하면 −0.003~−0.05).

## 학습·검증 구성
- **최종 학습 데이터: Train + Validation 97개 실험 전체** (원본 5초 간격 행 그대로. 테이블 모델은 증강·샘플 가중 없음, CNN은 위 2번의 증강·가중 사용).
- **검증 방법**
  - 주 검증: Train+Validation 97개 실험을 실험 단위로 층화(bat_class × tr_method) 5-fold × 3회 반복.
    Test는 500행이 넘는 실험을 500행으로 균등 다운샘플해 두었으므로, 검증 행도 같은 방식으로 다운샘플하고
    검증 행의 시계열 피처는 그 행들만 보고 만듭니다 (Test에서 보이는 조건과 동일).
  - 보조 검증: 대회 제공 분할 (Train 78개 실험으로 학습 → Validation 19개 실험 평가).
- **검증 점수 (Macro F1)**
  - 5-fold × 3회 교차검증 (테이블 모델, Test식 다운샘플 행 채점): 기본 모델 0.9074 → **2·3단계 재판정 포함 0.9120**
    (실험 단위 부트스트랩 90% 구간 0.891~0.927. 재판정의 효과 +0.0046, 짝지은 부트스트랩에서 개선일 확률 0.99.
    2단계 F1 0.814 → 0.832, 3단계 F1 0.902 → 0.912, 4~6단계는 변화 없음). 5단계 근거 확인까지 넣으면 0.9122, 6단계 근거 확인까지 넣으면 0.9146, 되돌아가지 않기까지 넣으면 0.9203, 원통형 4단계 최소 길이까지 넣으면 0.9212, 각형 6단계 진입까지 넣으면 0.9224, 원통형 두 번째 전압 강하 기준을 다듬은 최종 구성은 **0.9229** (90% 구간 0.905~0.936).
    이미지 CNN 융합(w=0.2)은 교차검증에서 ±0.001 이내로 점수에는 중립이었습니다 — 이미지 사용 요건을 위해 넣었고,
    가중치 0.2는 검증 결과를 보고 그 이상 키우지 않은 값입니다.
  - 제공 분할 Train 78개 → Validation 19개 실험 (`train.py --eval_cnn` 출력):

    | 검증 행 | 테이블 단독 | 테이블 + 규칙 보정 | CNN 단독 | 융합 | 융합 + 규칙 보정 (최종 방식) |
    |---|---|---|---|---|---|
    | Test식 다운샘플 (6,514행) | 0.8834 | 0.9271 | 0.7581 | 0.8758 | **0.9272** |
    | Validation 원본 행 (10,200행) | 0.8431 | 0.9131 | 0.7055 | 0.8345 | **0.9178** |

    (제공 Validation은 19개 실험뿐이라 점수 흔들림이 큽니다. 원본 행 점수는 긴 실험 몇 개가 행의 66%를 차지해 Test와 가중이 다릅니다.)
    규칙의 구조와 상수는 Validation 19개를 포함한 97개 실험을 보고 정했으므로, 위 표의 '규칙 보정' 열은 모델에 대해서만
    hold-out이고 규칙에 대해서는 아닙니다 (교차검증의 규칙 효과도 같습니다).
  - 규칙 상수의 과적합 점검 (`experiments/checks/nested_constants.py`): 실험 절반의 라벨만으로 상수 4개(원통형 4단계 최소 길이,
    각형 최고점 하강, 급상승 속도·10초 상승)를 정해진 절차로 다시 정해 나머지 절반에 적용하기를 40회 반복했습니다.
    규칙 전체의 효과는 +0.0155(최종 상수) → +0.0135(절반에서 정한 상수)였고, 40회 중 95%에서 이득이었습니다.

## 시계열 피처 구성
모든 시계열 피처는 같은 `experiment_id` 안에서 `relative_time_s`로 정렬한 뒤 **현재 시점 이하의 관측만** 사용합니다(인과적).
윈도우는 행 수가 아니라 **초 단위**입니다 (학습 데이터의 5초 간격과 Test의 10·15초 간격에서 같은 의미).
추론 대상 실험의 미래 관측, 실험 전체 기준 통계(평균·최댓값·길이·순위), 다른 실험의 관측은 쓰지 않습니다.
학습 데이터에서 산출해 `weights/`에 저장하는 통계는 하나뿐입니다: 배터리 구성별 압력 범위 중앙값 (아래 압력 상승 피처의 단위 환산용).
- **원시 값 (23)**: `relative_time_s`, 센서 4개(`meas_v`, `meas_t1`, `meas_t2`, `meas_p`; `meas_a`는 항상 0이라 제외),
  가스 10종, `atmp_t`, `thermal_t`, `indu_t`(+결측 여부), 배터리 메타 4개. `indu_t.1`은 Test에서 전부 결측이라 쓰지 않습니다.
- **이미지 색 통계 (11)**: 열화상의 무지개 의사색상을 색조(hue)로 의사 온도(0~1)로 되돌린 뒤 평균·표준편차·분위수·최댓값·
  임계 초과 비율·흰색 비율. 이미지마다 독립 계산, 고정 상수만 사용.
- **과거 윈도우 통계 (110)**: 센서 4개 + 이미지 신호 3개(`pt_mean`, `pt_p90`, `pt_frac50`) + `thermal_t`, `meas_co`, `meas_co2`, `indu_t`
  에 대해 과거 30/120/300초 구간 `(t−W, t]`의 평균·최댓값·최솟값, 120초 표준편차.
- **변화량·변화율 (110)**: 같은 신호의 15/30/60/120/300초 전(그 시각 이하 마지막 관측) 대비 변화량과 초당 변화율.
- **이벤트 경과 시간 (12)**: `meas_t1`이 45/60/80/100/150/300℃, `meas_t2`가 100/200℃에 처음 도달한 뒤 경과 초,
  전압이 지금까지 최댓값의 90/50/10% 아래로 처음 내려간 뒤, 0.05V 아래로 내려간 뒤 경과 초.
- **규칙 피처 (30, `r_*`)**: 학습 데이터에서 라벨 전환 시점을 분석해 찾은 상수 임계값 기반 피처.
  `meas_t1` 45/50℃ 도달 후 경과 초, 압력 상승, 직전 관측 대비 전압 급락(−0.56V 이하 또는 2.5V 미만) 이후 경과 초와 횟수,
  배터리 종류별 5단계 조건(전압 1.355V 이하 / 0V / 온도 상승률), `t1+t2`의 지금까지 최댓값과 그 이후 하강,
  조건이 발화한 가장 높은 단계(`r_stage`) 등. 직전 관측 기준 차분과 초당 변화율, 지금까지의 누적값만 사용합니다.
- **압력 상승 피처 (48, `q_*`, 2·3단계 재판정 모델 전용)**: 3단계는 "표면 온도 50~90℃에서 압력이 연속으로 오르기 시작하는 지점"입니다.
  - 5/10/15/20/30초 전(그 시각 이하 마지막 관측) 대비 압력 상승량과, 온도 조건을 만족한 상승량의 지금까지 최댓값.
    온도 조건은 "그 과거 시점의 온도"와 "현재 온도" 두 가지로 봅니다.
  - 상승량의 단위: ① 학습 실험에서 구한 같은 배터리 구성(종류·용량·유발 방식)의 압력 범위(최댓값 − 최솟값) 중앙값으로 나눈 값,
    ② 그 실험의 첫 관측 압력으로 나눈 값. ①의 중앙값 표는 학습 데이터에서만 산출해 `weights/tab_lgbm.joblib`에 저장합니다.
    학습 행의 피처는 "자기 실험을 뺀" 중앙값으로 계산해 추론 조건과 맞췄습니다.
  - 상승량이 임계(0.01~0.08)를 처음 넘은 뒤 경과 초, 지금까지의 최솟값 대비 압력 수준, `meas_t1`이 50℃에 처음 도달한 뒤 경과 초.
  - 각형 280Ah 가열, 파우치 73Ah 가열(SOC 50%) 실험은 판정 기준이 달라 이 피처를 비워 둡니다(결측 처리, LightGBM이 그대로 처리).
- **이미지 CNN의 시간 정보**: 현재 프레임과 같은 실험의 직전 관측 프레임(과거)의 차이만 사용합니다.

### 라벨 정의를 확인한 자료
- 2~6단계가 센서 값 규칙으로 붙여졌다는 것은 학습 데이터 분석으로 먼저 찾았고(2단계 = `meas_t1` 45℃ 도달, 97개 실험 전부 일치),
  3단계의 정의는 원본 데이터셋의 **공개 구축 가이드 문서**(AI Hub "배터리 열폭주 제어 멀티모달 데이터" 활용 가이드라인)를 읽고 확인했습니다.
- 가이드의 판정식은 "20초 뒤 압력"과 "실험 전체 범위로 정규화한 값"을 씁니다. 이는 대회 규칙이 금지하는 미래 관측·실험 전체 통계에
  해당하므로 **그대로 쓰지 않았고**, 위와 같이 과거 관측과 학습 데이터 통계만으로 근사했습니다.
- 참고한 것은 문서뿐입니다. 원본 데이터셋의 데이터·라벨은 내려받거나 사용하지 않았습니다.

### 남은 손실이 어디에 있는가
`experiments/checks/ceiling.py` (분석 전용). Test에 있는 배터리 구성의 교차검증 점수는 0.9349입니다.
